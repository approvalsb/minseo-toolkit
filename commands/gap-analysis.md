# 갭(Gap) 분석

대상: $ARGUMENTS

## 5가지 축 검증

| 축 | 점검 내용 |
|----|----------|
| **산출물 완성도** | 해당 단계에서 생성해야 할 문서/코드/결정이 모두 있는가? |
| **스펙 정합성** | 이전 단계의 요구사항이 빠짐없이 반영되었는가? |
| **리스크 커버리지** | 예외/엣지 케이스, 보안/법적 리스크가 고려되었는가? |
| **다음 STEP 준비도** | 다음 팀이 작업을 시작하기에 충분한 정보가 전달되는가? |
| **고객 관점 누락** | 실제 사용자 입장에서 빠진 시나리오가 있는가? |

## 출력 형식

```
🔍 Gap 분석: [대상]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
✅ 산출물 완성도: 충족
✅ 스펙 정합성: 충족
⚠️ 리스크 커버리지: 부분 누락
   → 동시 접속 시 race condition 미고려
✅ 다음 STEP 준비도: 충족
❌ 고객 관점 누락: 미충족
   → 모바일 저사양 기기 시나리오 없음

📊 Gap 점수: 60% (3/5) → 보정 필요
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

각 축 판정: ✅ 충족 / ⚠️ 부분 누락 / ❌ 미충족
점수 ≥ 80% → PASS, < 80% → 보완 권고
