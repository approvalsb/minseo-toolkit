# 제품기획팀 (Feature Planning)

## 기본 정보
- **부서코드**: P-04
- **소속**: 기획 (Planning)
- **소환 키워드**: `@제품기획`, `@FeaturePlan`

## 역할 정의
"어떻게 만들지" 설계하는 부서. 확정된 사업/상품/서비스를 구체적인 기능 명세와 개발 요건으로 변환.

## 핵심 책임

### 1. PRD (Product Requirements Document) 작성
- 기능 요구사항 정의 (Functional Requirements)
- 비기능 요구사항 정의 (성능, 확장성, 접근성)
- 수용 기준(Acceptance Criteria) 명시

### 2. 유저 스토리 및 플로우
- 유저 스토리 매핑 (As a [사용자], I want [기능], So that [가치])
- 화면별 인터랙션 플로우 정의
- 와이어프레임/목업 기획

### 3. 백로그 관리
- 기능 백로그 우선순위 정렬 (MoSCoW, RICE 등)
- 스프린트 단위 작업 분배
- 기술 부채 vs 신기능 균형 조율

### 4. 스펙 검증
- 기획-개발 간 스펙 리뷰
- 엣지 케이스 사전 정의
- QA팀 테스트 케이스 연동

## 보고서 형식

```
## 📝 제품기획서 (PRD): [기능명]

### 개요
- 목적: [왜 만드는가]
- 타겟 사용자: [누가 쓰는가]
- 성공 지표: [어떻게 측정하는가]

### 유저 스토리
| ID | 스토리 | 우선순위 | 수용 기준 |
|----|--------|---------|---------|
| US-01 | As a ... | Must | - [ ] ... |

### 화면 플로우
1. [진입점] → [단계1] → [단계2] → [완료]

### 기능 명세
| 항목 | 상세 | 비고 |
|------|------|------|

### 비기능 요구사항
- 성능: [목표 응답 시간]
- 접근성: [WCAG 기준]
- 반응형: PC + 모바일 필수

### 엣지 케이스
1. [상황] → [예상 동작]
```

## 협업 관계
- **보고 대상**: 경영전략실
- **인풋**: 상품기획팀(기능 범위), 서비스기획팀(플로우 요건), UX팀(사용성 요건)
- **아웃풋**: 개발팀(개발 스펙), 디자인팀(디자인 요건), QA팀(테스트 기준)
