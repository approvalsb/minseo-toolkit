# Part 1: 부서 간 협업 플랜

## 1.1 본부 내부 협업 체계

### 📋 기획본부 내부 (4개 팀)
```
사업기획 ──→ 상품기획 ──→ 서비스기획 ──→ 제품기획
"할지 말지"   "뭘 팔지"    "어떻게 제공"   "어떻게 만들지"
```
- **협업 규칙**: 반드시 순차 진행. 앞 단계 승인 없이 다음 단계 착수 불가.
- **핸드오프 문서**: 각 단계 완료 시 다음 팀에 전달할 표준 문서 생성
  - 사업기획 → 상품기획: `사업 타당성 보고서`
  - 상품기획 → 서비스기획: `상품 구성안`
  - 서비스기획 → 제품기획: `서비스 블루프린트`
  - 제품기획 → 개발팀: `PRD (Product Requirements Document)`

### ⚙️ 엔지니어링본부 내부 (5개 팀)
```
개발 ←──→ 자동화 (기능 연동)
  ↓
인프라 (배포)
  ↓
QA (테스트) + 보안 (감사)
```
- **협업 규칙**: 개발과 자동화는 병렬 작업 가능. QA와 보안은 개발 완료 후 병렬 검증.
- **일일 체크**: 빌드 상태, 배포 상태, 보안 알림 공유

### 📣 그로스본부 내부 (3개 팀)
```
마케팅 (전략) ←──→ 콘텐츠 (소재)
        ↓
    세일즈 (전환)
```
- **협업 규칙**: 마케팅이 전략/키워드 → 콘텐츠가 소재 제작 → 세일즈가 리드 전환
- **주간 싱크**: 광고 성과 리뷰 + 소재 효과 분석 + 리드 품질 피드백

## 1.2 본부 간 횡단 협업 (Cross-Functional Workflows)

### 🔄 워크플로우 A: 신규 사업 런칭 (End-to-End)
```
경영전략실 (방향 승인)
    ↓
기획본부 (사업→상품→서비스→제품)
    ↓
제품본부 (UX 설계 → UI 디자인)  ←── 고객단 (초기 피드백)
    ↓
엔지니어링 (개발 → 인프라 배포)
    ↓
QA + 보안 (검증)
    ↓
고객단 (출시 전 심사)  ←── 감사팀 (정합성 검증)
    ↓
그로스 (마케팅 준비 → 런칭)
    ↓
운영지원 (CS 준비 + 데이터 추적)
```

**체크포인트 게이트:**
| 게이트 | 승인 주체 | 통과 조건 |
|--------|---------|---------|
| G1: 사업 승인 | 경영전략실 + 재무 | 사업 타당성 + BEP 확인 |
| G2: 기획 완료 | 감사팀 | 기획 4단계 산출물 정합성 |
| G3: 개발 완료 | QA + 보안 | 테스트 통과 + 보안 감사 통과 |
| G4: 출시 승인 | 고객단 + 법무 | 고객단 80점+ / 법무 통과 |
| G5: 런칭 | 경영전략실 | 전 게이트 통과 최종 확인 |

### 🔄 워크플로우 B: 기능 개선/버그 수정 (Agile Loop)
```
CS (VOC/버그 접수) → 제품기획 (우선순위 결정) → 개발 (구현)
    → QA (테스트) → 인프라 (배포) → CS (고객 알림)
```
- 사이클 타임 목표: 버그 수정 1~3일, 기능 개선 1~2주

### 🔄 워크플로우 C: 마케팅 캠페인 집행
```
마케팅 (전략 수립) + 상품기획 (소구점)
    ↓
콘텐츠 (카피) + 디자인 (비주얼)
    ↓
보안 (랜딩페이지 검증) + 법무 (광고 법규 검토)
    ↓
데이터분석 (예상 성과) → Go/No-go
    ↓
마케팅 (집행) → 데이터분석 (실시간 추적) → 세일즈 (리드 전환)
```

### 🔄 워크플로우 D: 요금제/가격 변경
```
상품기획 (변경안) + 재무 (마진 시뮬레이션)
    ↓
서비스기획 (운영 정책 반영) + 법무 (약관 검토)
    ↓
개발 (결제 로직 수정) + QA (결제 테스트)
    ↓
고객단 (가격 수용성 심사)
    ↓
CS (기존 고객 안내 준비) + 마케팅 (공지/프로모션)
```

### 🔄 워크플로우 E: 고객단 피드백 반영 루프
```
고객단 (심사 결과)
    ↓
UX (사용성 이슈 분류) + 디자인 (비주얼 이슈 분류)
    ↓
제품기획 (우선순위 결정)
    ↓
개발 (구현) → QA (검증) → 고객단 (재심사)
```

## 1.3 부서 간 상시 협업 매트릭스

어떤 부서가 어떤 부서와 정기적으로 소통해야 하는지를 정의합니다.

| 협업 쌍 | 주기 | 공유 내용 |
|---------|------|---------|
| 마케팅 ↔ 콘텐츠 | 주 2회 | 키워드, 소재 요청, 성과 피드백 |
| 마케팅 ↔ 데이터분석 | 주 1회 | ROAS, 전환율, 채널별 성과 |
| 세일즈 ↔ CS | 주 1회 | 신규 고객 인수인계, 이탈 고객 정보 |
| 개발 ↔ QA | 매일 | 빌드 상태, 버그 현황 |
| 개발 ↔ 보안 | 주 1회 | 코드 리뷰, 취약점 스캔 결과 |
| 제품기획 ↔ UX | 주 1회 | 유저 스토리 검토, 사용성 테스트 결과 |
| UX ↔ 디자인 | 주 2회 | UX→UI 핸드오프, 디자인 리뷰 |
| 상품기획 ↔ 재무 | 격주 | 요금제 마진, 비용 변동 |
| 서비스기획 ↔ 법무 | 필요시 | 약관/정책 변경 시 즉시 협의 |
| 자동화 ↔ 인프라 | 주 1회 | 크론/파이프라인 상태, 서버 리소스 |
| CS ↔ 제품기획 | 주 1회 | VOC 요약, 기능 요청 우선순위 |
| 감사 ↔ 전 부서 | 월 1회 | 교차 검증 결과, 정합성 보고 |

# Part 2: 보고 체계

## 2.1 정기 보고 체계

### 📅 일간 보고 (Daily Brief)
- **시점**: 매일 업무 시작 시
- **형식**: 간결한 상태 업데이트
- **보고 부서**: 엔지니어링 본부 (개발, 인프라)
- **내용**:
  - 어제 완료한 작업
  - 오늘 진행할 작업
  - 블로커/이슈

```
## 📌 일간 브리프: YYYY-MM-DD

### ✅ 어제 완료
- [부서] [작업 내용]

### 🔄 오늘 진행
- [부서] [작업 계획]

### 🚨 블로커
- [부서] [이슈 + 필요한 지원]
```

### 📅 주간 보고 (Weekly Report)
- **시점**: 매주 금요일
- **형식**: 본부별 종합 보고
- **보고 부서**: 전 본부 (본부장 역할의 대표 부서가 취합)
- **보고 대상**: 경영전략실 → 대표 보고

```
## 📊 주간 보고서: YYYY-MM-DD 주차

### 경영진 요약 (Executive Summary)
- [3줄 이내 핵심 요약]

### 본부별 현황
#### 기획본부
- 진행: [주요 기획 건]
- 완료: [완료 건]
- 이슈: [미결 사항]

#### 엔지니어링본부
- 배포: [이번 주 배포 내역]
- 버그: [발견/수정 건수]
- 인프라: [서비스 가용성, 장애 여부]

#### 그로스본부
- 마케팅: [광고 성과 요약]
- 콘텐츠: [발행 건수, 성과]
- 세일즈: [리드/전환 현황]

#### 운영지원본부
- 데이터: [핵심 KPI 변동]
- CS: [문의 건수, 해결률]
- 재무: [비용/수익 요약]

### 다음 주 계획
| 본부 | 핵심 과제 | 담당 |
|------|---------|------|

### 대표 결재 필요 사항
1. [승인/결정 필요 항목]
```

### 📅 월간 보고 (Monthly Report)
- **시점**: 매월 말일
- **형식**: 전사 종합 성과 보고
- **작성**: 비서실 (전 부서 데이터 취합)

## 2.2 긴급 보고 체계

긴급 상황 발생 시 정기 보고를 기다리지 않고 **즉시 보고**합니다.

### 🔴 긴급 보고 트리거 및 경로

| 상황 | 심각도 | 최초 감지 | 즉시 보고 대상 | 보고 시한 |
|------|--------|---------|-------------|---------|
| **서비스 장애** (다운타임) | Critical | 인프라/QA | 경영전략실 + 개발 | 발생 즉시 |
| **보안 침해** (해킹, 데이터 유출) | Critical | 보안 | 경영전략실 + 법무 + 인프라 | 발생 즉시 |
| **법적 문제** (소송, 규제 위반 통보) | Critical | 법무 | 경영전략실 | 인지 즉시 |
| **결제 시스템 장애** | Critical | QA/CS | 경영전략실 + 개발 + 재무 | 발생 즉시 |
| **API 키 유출** | High | 보안 | 인프라 + 경영전략실 | 발생 즉시 |
| **광고 예산 급소진** (일일 한도 초과) | High | 마케팅/데이터 | 경영전략실 + 재무 | 1시간 이내 |
| **고객 대량 이탈** (일일 이탈 2배 초과) | High | 데이터/CS | 경영전략실 + 서비스기획 | 당일 |
| **빌드 실패** (프로덕션 배포 불가) | Medium | 개발/인프라 | 엔지니어링 본부 내 | 당일 |
| **부정적 여론** (SNS 바이럴) | Medium | 마케팅/CS | 경영전략실 + 콘텐츠 | 당일 |

### 긴급 보고서 형식

```
## 🚨 긴급 보고: [상황 요약]
일시: YYYY-MM-DD HH:MM
심각도: 🔴 Critical / 🟡 High / 🟢 Medium
보고자: [부서명]

### 상황 설명
- 무엇이: [문제 내용]
- 언제: [발생 시점]
- 영향 범위: [영향 받는 서비스/고객 수]

### 현재 상태
- [ ] 문제 파악 완료
- [ ] 원인 분석 중
- [ ] 임시 조치 완료
- [ ] 근본 해결 완료

### 즉시 조치 사항
1. [이미 취한 조치]
2. [추가 필요 조치]

### 필요 지원
- [타 부서 협조 요청 사항]

### 예상 복구 시간
- [ETA]
```

### 긴급 보고 에스컬레이션 경로
```
Level 1: 담당 부서 자체 해결 시도 (15분)
    ↓ 미해결 시
Level 2: 관련 본부 내 협업 (30분)
    ↓ 미해결 시
Level 3: 경영전략실 보고 + 타 본부 지원 요청
    ↓ 미해결 시 / Critical 즉시
Level 4: 대표 직보 + 전사 대응 체제
```

## 2.3 상황별 개별 보고 체계

특정 상황 발생 시 해당 부서가 대표(경영전략실 경유)에게 개별 보고하는 체계입니다.

### 📌 사업/전략 관련

| 상황 | 보고 부서 | 보고 형식 | 경유 |
|------|---------|---------|------|
| 신규 사업 제안 | 사업기획 | 사업 타당성 보고서 | 경영전략실 승인 |
| 사업 철수/피봇 권고 | 사업기획 + 데이터 | Go/No-go 분석서 | 경영전략실 결재 |
| 시장 환경 급변 | 사업기획 | 긴급 시장 분석 | 경영전략실 직보 |
| 경쟁사 주요 동향 | 마케팅 | 경쟁 분석 브리프 | 경영전략실 공유 |

### 💰 재무 관련

| 상황 | 보고 부서 | 보고 형식 | 경유 |
|------|---------|---------|------|
| 월 비용 예산 80% 도달 | 재무 | 비용 경고 보고 | 경영전략실 직보 |
| 예상 외 비용 발생 | 재무 + 해당 부서 | 비용 분석 + 대안 | 경영전략실 승인 |
| 요금제 변경 필요 | 상품기획 + 재무 | 가격 변경 제안서 | 경영전략실 결재 |
| API 비용 급증 | 인프라 + 재무 | 비용 분석 + 최적화안 | 경영전략실 공유 |

### 🔧 기술 관련

| 상황 | 보고 부서 | 보고 형식 | 경유 |
|------|---------|---------|------|
| 주요 기술 스택 변경 | 개발 | 기술 의사결정 문서 (ADR) | 경영전략실 승인 |
| 기술 부채 임계점 도달 | 개발 + QA | 기술 부채 보고서 | 경영전략실 공유 |
| 외부 API 중단/변경 | 개발 + 자동화 | 영향도 분석 + 대응안 | 경영전략실 공유 |
| 인프라 확장 필요 | 인프라 + 재무 | 인프라 증설 제안서 | 경영전략실 결재 |

### 📣 마케팅/세일즈 관련

| 상황 | 보고 부서 | 보고 형식 | 경유 |
|------|---------|---------|------|
| 캠페인 성과 이상 (ROAS < 1) | 데이터 + 마케팅 | 성과 분석 + 대응안 | 경영전략실 공유 |
| 대형 리드/파트너십 발생 | 세일즈 | 딜 브리프 | 경영전략실 직보 |
| 채널 전략 변경 필요 | 마케팅 + 데이터 | 채널 분석 보고서 | 경영전략실 승인 |
| SNS 위기 관리 | 콘텐츠 + 마케팅 | 위기 대응 보고 | 경영전략실 즉시 |

### ⚖️ 법무/컴플라이언스 관련

| 상황 | 보고 부서 | 보고 형식 | 경유 |
|------|---------|---------|------|
| 법규 변경 영향 | 법무 | 법규 영향 분석서 | 경영전략실 직보 |
| 고객 클레임 (법적 수준) | 법무 + CS | 법적 리스크 평가 | 경영전략실 즉시 |
| 개인정보 사고 | 보안 + 법무 | 사고 보고서 + 대응안 | 경영전략실 즉시 |
| 약관/정책 변경 필요 | 법무 + 서비스기획 | 정책 변경 제안서 | 경영전략실 결재 |

### 👥 고객 관련

| 상황 | 보고 부서 | 보고 형식 | 경유 |
|------|---------|---------|------|
| 고객단 심사 불합격 (60점 미만) | 고객단 + UX | 심사 보고서 + 개선안 | 경영전략실 공유 |
| VOC 트렌드 변화 | CS + 데이터 | VOC 분석 보고 | 제품기획 + 경영전략실 |
| 대량 이탈 징후 | CS + 데이터 | 이탈 분석 + 윈백안 | 경영전략실 직보 |
| 핵심 고객 불만 | CS + 세일즈 | 고객 대응 보고 | 경영전략실 공유 |

## 2.4 보고서 라우팅 규칙

### 결재 등급

| 등급 | 의미 | 경로 |
|------|------|------|
| **직보** | 경영전략실에 직접 보고 (대표 즉시 전달) | 부서 → 경영전략실 → 대표 |
| **결재** | 경영전략실 검토 후 대표 승인 필요 | 부서 → 경영전략실 검토 → 대표 결재 |
| **승인** | 경영전략실 선에서 승인 가능 | 부서 → 경영전략실 승인 |
| **공유** | 정보 공유 목적 (결재 불필요) | 부서 → 경영전략실 + 관련 부서 공유 |

### 보고서 전달 시 비서실 역할
1. **취합**: 복수 부서 보고가 필요한 경우 비서실이 취합하여 단일 문서로 정리
2. **포맷 통일**: 보고서 형식이 다를 경우 비서실이 표준 형식으로 변환
3. **우선순위 태깅**: 긴급도에 따라 [🔴 즉시] [🟡 금일] [🟢 정기] 태그 부착
4. **후속 추적**: 대표 지시사항을 해당 부서에 전달하고 이행 여부 추적

## 2.5 엔지니어링 회고 (Retro)

주기적으로 git 커밋 이력을 기반으로 **정량적 엔지니어링 회고**를 수행한다.
감이 아니라 데이터로 돌아보는 것이 핵심.

### 소환 및 옵션
| 명령어 | 동작 |
|--------|------|
| `@회고` / `@retro` | 최근 7일 회고 (기본) |
| `@회고 24h` | 최근 24시간 |
| `@회고 14d` | 최근 14일 |
| `@회고 30d` | 최근 30일 |
| `@회고 비교` | 이번 주 vs 지난 주 비교 |
| `@회고 전체` | 전 프로젝트 통합 회고 (멀티 레포) |

### 수집 데이터 (git log 기반)
1. **커밋 현황**: 총 커밋 수, 기여자, PR/MR 수
2. **LOC 분석**: 추가/삭제/순증, 테스트 LOC 비율
3. **시간 분포**: 시간대별 커밋 히스토그램 (야간 코딩 클러스터 감지)
4. **세션 감지**: 45분 공백 기준으로 작업 세션 분리 → 세션당 LOC/시간
5. **핫스팟 분석**: 가장 많이 수정된 파일 Top 10 (기술 부채 후보)
6. **테스트 건강도**: 전체 테스트 수, 이번 주기 추가분, 테스트 커버리지 변동

### 보고서 형식

```
## 🔄 엔지니어링 회고: [기간]

### 핵심 지표
| 지표 | 값 |
|------|-----|
| 커밋 수 | N |
| 기여자 | N명 |
| 총 추가 | +N lines |
| 총 삭제 | -N lines |
| 순증 LOC | +N lines |
| 테스트 LOC 비율 | N% |
| 활동 일수 | N일 |
| 감지된 세션 | N회 |
| 평균 LOC/세션시간 | N |

### 시간대별 분포
Hour  Commits  ████████████████
 09:    8      ████████
 14:   12      ████████████
 22:    3      ███
[피크 시간대, 야간 코딩 여부 코멘트]

### 핫스팟 (가장 많이 수정된 파일)
| 순위 | 파일 | 수정 횟수 | 주의 |
|------|------|---------|------|
| 1 | | | 리팩토링 후보? |

### 이번 주기 하이라이트
- 🟢 잘한 것: [구체적 성과]
- 🟡 개선점: [다음 주기에 시도할 것]
- 🔴 주의: [기술 부채, 야간 작업 패턴 등]

### 다음 주기 권고
1. [구체적 액션]
```

### 비교 모드 (`@회고 비교`)
이번 주기와 이전 동일 기간을 비교하여 트렌드를 보여준다.

```
| 지표 | 이번 주기 | 이전 주기 | 변동 |
|------|---------|---------|------|
| 커밋 수 | 45 | 32 | +41% |
| 순증 LOC | +2,400 | +1,800 | +33% |
| 테스트 비율 | 28% | 22% | +6%p |
```

### 전체 모드 (`@회고 전체`)
여러 프로젝트 레포를 순회하며 통합 회고를 생성한다.
각 프로젝트별 요약 + 전체 합산 지표 + 프로젝트 간 시간 배분 분석.

## 2.6 소환 명령어와 보고 체계 연결

사용자가 보고 관련 명령을 내릴 때의 표준 트리거:

| 명령어 | 동작 |
|--------|------|
| `일간 브리프` / `@데일리` | 엔지니어링 중심 일간 상태 보고 |
| `주간 보고` / `@위클리` | 전 본부 주간 보고서 생성 |
| `월간 보고` / `@먼슬리` | 전사 월간 경영 보고서 생성 |
| `긴급 보고 [상황]` | 긴급 보고서 양식으로 즉시 작성 |
| `[부서] 현황 보고해` | 해당 부서 개별 현황 보고 |
| `대표 보고 [주제]` | 비서실이 취합하여 대표 보고용 문서 작성 |
| `게이트 [G1~G5] 점검` | 해당 게이트 관련 부서들의 승인 여부 확인 |
| `@회고` / `@retro` | 엔지니어링 회고 (git 기반 정량 분석) |
